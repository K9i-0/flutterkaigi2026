# 映画ポスター制作

作品固有のバカさ、恐怖、アクションなどは自由に設計し、納品仕様だけを固定する。SNS安全域とタイトル位置は確認の目安とし、ユーザーの依頼なしに構図を追い込まない。

## 必須仕様

- 本番画像を縦2:3、1024×1536 px、PNG、RGBまたはRGBAで作る。
- 引き伸ばして比率を合わせない。必要なら左右をアウトペイントし、上下の余白を再構成する。
- SNSクロップはプレビューで確認するが、ユーザーがSNS対応や位置修正を求めていない限り、タイトル位置を理由に再編集しない。
- タイトル、コピー、公開表記はユーザー指定の文字列を一字ずつ照合する。画像内に不要な文字を追加しない。
- キャラクターの人物同一性を維持する。実写メンバーは正典写真の顔、非実写キャラクターは各ファイルの「人物同一性」に記載した識別要素を基準にする。衣装、持ち物、表情、体格、配色、役割はユーザー指定に従う。
- よーたん、福ちゃん、とーくん、おかやまんを実写表現で出す場合は、正典写真を顔の最上位参照として直接使う。衣装だけ合った別人を合格にしない。
- 生成後に画像を目視し、検査スクリプトを実行する。検査前の画像を本番扱いしない。
- 生成済み画像を世代ごとに連続編集しない。修正時は高品質な元案または原典資料へ戻り、累積FBを一度に適用する。

数値と配置の詳細は [references/poster-standard.md](references/poster-standard.md) を読む。

## 制作手順

1. 対象フォルダを `rg --files` で確認し、台本、キャラクター資料、ロゴ、既存ポスターを特定する。
2. `01_WORLD/` と該当する `02_CHARACTERS/*.md` を読み、人物同一性の識別要素だけを抜き出す。世界観と過去エピソードは発想材料に限り、ユーザー指定を制限しない。実写4名が登場する場合は [references/live-action-face-canon.md](references/live-action-face-canon.md) も必ず読む。
3. 既存画像を編集する場合は、編集前に必ず画像を表示して確認する。
4. [assets/poster-brief-template.md](assets/poster-brief-template.md) の項目を作業メモとして埋める。ユーザーが指定していない宣伝文句を勝手に確定しない。
5. `imagegen` スキルを読み、初回は同じ原典資料から独立したA/B/Cの3案を作る。前の案を次の案の編集元にしない。実写4名が出る場合は、該当する正典写真を3案すべてへ直接渡す。
6. 3案は構図、主役の見せ方、色調、タイトル処理のうち少なくとも2項目を明確に変える。単なる微差にしない。
7. 文字列を限定列挙し、`No other text` を指定する。複雑なタイトルロゴはロゴ参照画像を別に用意し、厳密な参照として渡す。
8. A/B/Cを並べ、ブリーフへの一致度が最も高い案を一つ推奨する。ユーザーが別案を選んだらその選択を優先し、選択せず続行を求めた場合は推奨案を使う。
9. 生成結果を表示し、構図、人物数、キャラクター同一性、文字、余計なロゴ、画像端での欠けを目視確認する。
10. 次のコマンドで寸法とSNSクロップを検査する。

```bash
python3 .claude/skills/create-movie-poster/scripts/audit_movie_poster.py \
  path/to/poster.png --preview-dir /tmp/movie-poster-audit
```

11. 4:5と1:1のプレビューは情報として表示する。ユーザーからSNS対応の指定またはタイトル位置の修正依頼がある場合だけ位置を調整する。
12. 合格した画像だけを対象作品フォルダへ保存し、実寸、採用案、変更点を報告する。

## 新規制作と改修の分岐

### 新規制作

- ポスターの中心となる一つの出来事を決める。
- 上段のコピー、中央の主役、下段のタイトルという基本階層から始め、必要な場合だけ崩す。
- 背景情報より主役のシルエットとタイトル可読性を優先する。
- 初回3案を `_variant_a`、`_variant_b`、`_variant_c` で保存し、採用案だけを本番ファイルへ昇格する。

### 既存ポスター改修

- ユーザーが触れていない人物、表情、色、文言、世界観を維持する。
- 比率変更では切り抜きよりアウトペイントを優先し、顔・手・小道具・ロゴを欠損させない。
- タイトル位置だけのFBでは、タイトル群と直下の公開表記以外を極力変えない。
- ユーザーがタイトル位置に触れていなければ、安全域に合わせるためだけの編集を行わない。
- 顔の修正では、崩れた生成顔を参照にせず、正典写真と選定案の高品質マスターから再生成する。

## 実写メンバーの顔

- よーたん、福ちゃん、とーくん、おかやまんの顔は、似た雰囲気の俳優ではなく正典写真と同一人物として生成する。
- 顔の輪郭、目の形と間隔、眉、鼻、口、顎を基準に同一人物性を維持する。髪、生え際、ひげ、年齢表現、美形化、老化、特殊メイク、変身はユーザー指定に従い、変更後も元の人物だと識別できるようにする。
- パロディやオマージュでは、構図、衣装的記号、場所、題字、ロゴ階層などをどこまで参照するかはユーザー指定を正本とし、元ネタの認知に必要な要素を推測で薄めない。
- 衣装、髪色、眼鏡などの記号が合っていても、顔が正典と一致しなければその案を不合格にする。
- 複数人が登場する場合は、プロンプト内で人物名と参照画像を一対一で対応づけ、顔を混ぜない。
- 顔が小さすぎて同一性を確認できない構図を主役案として推奨しない。生成後は顔を等倍または拡大表示して確認する。
- ユーザーが特殊メイク、年齢変更、顔の変形を明示した場合だけ、その変更を正典顔へ限定的に加える。

## 画質劣化を防ぐ

- A/B/Cをそれぞれ原典のキャラクター資料、ロゴ、背景資料から直接生成する。
- 実写4名が登場するA/B/Cでは、毎回同じ正典顔写真を直接参照する。別案や過去のポスターを顔の唯一の参照にしない。
- 選定案の元ファイルを不変のマスターとして残す。
- 2回目以降のFBでは直前の編集画像を再編集せず、マスターへ全FBをまとめて一度に適用する。原典からの再生成の方が忠実なら再生成する。
- 一度の修正で変更点を限定し、ユーザーが依頼していない安全域調整、色調補正、再レイアウトを混ぜない。
- 画質が落ちた案を納品候補にせず、マスターへ戻る。

## 文字とロゴの検査

- 画像に見える全文を声に出すつもりで一文字ずつ転記し、指定文と比較する。
- 「2」など色指定された文字だけが正しい色か確認する。
- タイトルアイコンと題字を一つのグループとして扱う。安全域への移動はユーザーが求めた場合だけ行う。
- 生成モデルが誤字を出した場合はそのまま納品せず、厳密なロゴ参照を使って再編集する。
- 実写4名がいる場合は、文字検査と同じ重要度で一人ずつ正典顔と照合する。

## ファイル運用

- 本番ファイルは原則 `poster_<作品slug>_production.png` とする。既存命名が定着している場合は維持する。
- 初回案は `_variant_a`、`_variant_b`、`_variant_c`、デバッグ版は `_debug` を付け、本番と区別する。
- 元の本番画像を置換する場合はユーザーの修正依頼を置換許可として扱う。別案を残す指示がある場合は新しい名前で保存する。
- 検査プレビューは作品フォルダへ常置せず、一時ディレクトリに出す。
