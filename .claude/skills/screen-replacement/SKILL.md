# 画面差し替え

平面画面の四隅をフレームごとに求め、正確な画像・動画をホモグラフィで合成する。生成素材、追跡データ、合成素材、完成編集を分離して再現可能に保つ。

## 発動条件

- ユーザーが画面差し替え、クロマキー、グリーン画面、画面追跡、合成の揺れ・色残りを明示した場合だけ使う。
- 動画内にモニターがあるだけで、グリーン化や画面置換を提案・適用しない。
- ユーザーがグリーン画面を明示していない既存素材を、勝手に再生成しない。
- Wanで新しくグリーン画面素材を作る場合は[生成ガイド](references/green-screen-generation.md)を読み、`wan-video`の課金・API・単一生成ルールにも従う。

## 方式を選ぶ

1. 緑の表示面がある場合は`green`方式を使う。HSV色領域から四隅を直接取り、前後フレームの二次曲線で平滑化する。
2. 通常画面しかない場合は`planar`方式を使う。最初の四隅を目視指定し、Lucas–Kanade光学フローとRANSACホモグラフィで追跡する。
3. 通常画面でドリフトする場合は、開始・中間・終了の四隅を手動キーフレーム化し、区間ごとの補正量を補間する。自動追跡の結果だけを正しいとみなさない。
4. 画面が曲面、強く反射、長時間遮蔽、モーションブラー、画面外へ出る場合は、区間分割、専用トラッカー、素材再生成を優先する。

## 素材を監査する

- `ffprobe`で解像度、fps、フレーム数、尺、音声を確認する。
- 差し替え区間の開始・終了を整数フレームへ固定する。
- 四隅が見えるか、ベゼルと表示面の境界、遮蔽、反射、緑と似た背景物を目視する。
- 差し替え内容はRemotion等で正確な静止画または動画として作り、生成映像内の文字を正本にしない。
- 元動画、採用音声、ロゴ、差し替え素材を上書きしない。比較版は別名で残す。

## 追跡する

OpenCV環境へ`opencv-python`と`numpy`を入れる。リポジトリに既存venvがある場合はそれを再利用する。

### グリーン方式

```bash
python3 <skill>/scripts/track_screen.py input.mp4 \
  --mode green \
  --source-start 0 --source-end 119 \
  --composition-start 0 \
  --output-json track.json \
  --preview track-preview.mp4
```

既定値は今回の検証済み設定とする。

- HSV: H 32–92、S 80–255、V 35–255
- 平滑化: 前後9フレーム、計19フレームの二次多項式
- 四隅拡張: 外側7px
- 最大の緑連結領域を表示面とする

背景の植物等が混ざる場合は彩度下限を上げる。暗い緑が欠ける場合はV下限を下げる。先にプレビューを直し、合成画像のサイズ調整で追跡誤差を隠さない。

### 通常画面方式

四隅は`TL;TR;BR;BL`順で指定する。

```bash
python3 <skill>/scripts/track_screen.py input.mp4 \
  --mode planar \
  --source-start 150 --source-end 209 \
  --composition-start 798 \
  --corners '126,91;655,99;648,382;141,438' \
  --smoothing-mode none \
  --output-json track.json \
  --preview track-preview.mp4
```

通常画面では画面内の特徴点が消えると追跡できない。フォールバック、インライア数、四隅の飛びを確認し、必要なら手動キーフレーム補正を追加する。
既定では1フレームで40pxを超える四隅ジャンプを拒否して前位置を保持する。フォールバックが出た区間は合格扱いにせず、四隅の再指定か手動キーフレーム補正を行う。

## 合成する

```bash
python3 <skill>/scripts/composite_screen.py input.mp4 \
  --screen screen.png \
  --track-json track.json \
  --output replaced.mp4 \
  --edge-inset 0 --feather 0.8 \
  --fade-in 0 --fade-out 0 \
  --preserve-audio --overwrite
```

- 静止画と動画の両方を差し替え素材にできる。
- グリーン方式は拡張済み四隅で緑縁を覆うため、原則`edge-inset 0`を使う。
- 通常画面でベゼルへはみ出す場合だけ1–3px内側へ入れる。
- 差し替え素材の縦横比を画面へ合わせ、CSSの長方形変形ではなく3×3ホモグラフィで焼き込む。
- フル動画へ組み込む場合は合成済み区間をRemotionの整数フレームで差し込み、字幕、UI、コメント、音声を上層で維持する。

## 揺れと緑残りを直す

- プルプルは輪郭点の量子化が大きな文字へ増幅されることで起きる。単純な移動平均や因果フィルタで遅らせず、中央の局所多項式を使う。
- カメラ移動が緩い素材では半径9、二次を出発点にする。意図した急な動きが鈍る場合は半径を5–7へ下げる。
- 緑残りは平滑化後の四隅を3–7px外側へ広げて覆う。黒ベゼルを侵食しすぎない最大値を目視で決める。
- 追跡プレビュー、差し替え完成、修正前後の左右比較を作る。静止画だけで揺れを合格にしない。

## 最終監査

1. 全対象フレームで検出・合成できたことを確認する。
2. 四隅のフレーム間移動と二階差分を測り、修正前より低下したことを記録する。
3. 差し替え四角形内の高彩度緑残りを測る。目安は平均0.05%未満とし、黒ベゼル侵食も同時に目視する。
4. 切替前後、最大遠近、最大移動、遮蔽、最終フレームを確認する。
5. 完成動画を終端までデコードし、尺、fps、フレーム数、音声を`ffprobe`で確認する。
6. `script.md`へ入力、追跡方式、HSV、平滑化、拡張量、出力、比較結果を記録する。

## 成果物

- 追跡JSON
- 四隅プレビュー動画
- 差し替え素材の正本画像または動画
- 合成済み区間
- フル尺完成版と修正前後比較版
- 再現コマンドと監査記録

生成動画とプレビューはGit管理せず、スクリプト、設定、軽量な追跡JSON、編集コードだけを追跡する。
