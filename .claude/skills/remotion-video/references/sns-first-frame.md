# SNS用先頭1フレーム

## 選定

- まず通常完成版の先頭フレームを抽出して確認する。顔・主題が読み取れ、興味を引き、ネタばれがなければそのまま採用し、不要な差し替えや選択待ちを増やさない。
- 差し替えが必要なら、字幕・テロップを含む完成編集後の動画から、異なる構図・状況の候補を目安4〜6枚選ぶ。弱い候補で数を埋めない。元の先頭も比較用に提示する。
- 候補には番号、元動画のフレーム番号・時刻、興味を引く理由、ネタばれ懸念を添え、一覧画像で比較できるようにする。人が番号で採用を決める。ユーザーが選択を委任していない限り、回答待ちを自動採用に置き換えない。通常完成版の編集・監査は並行して進めてよい。
- 結末よりも「何が起こるのか」が気になる状況を優先する。人物同一性、縮小表示での読みやすさ、顔・小道具の明瞭さ、字幕によるネタばれを確認する。瞬き、ブレ、カット途中の混合画像、本編にない出来事を示す画像は避ける。ユーザーの明示した先出し演出は優先する。

## 編集

- 通常完成版を保持し、差し替える場合のみ別のSNS版をエピソード直下の`final_remotion_sns.mp4`へ出力する。採用画像は本番入力PNGとして保持する。
- Remotionの全体フレーム`0`だけに、採用PNGを不透明・全面の最上層として表示する。通常の映像・字幕・ロゴはフレーム`1`から元の同じ時刻を表示する。画像の上に元時刻の字幕を重ねて二重表示しない。
- ベース動画と音声の開始位置は動かさない。映像トラックへの1フレーム挿入、音声の切除、総フレーム数の変更、静止画の0.5〜1秒保持は行わない。1フレームの長さは完成版のfpsに従い、30fpsへ強制しない。
- 既存プロジェクトの編集コードへ実装し、未対応のmanifest項目が既に機能すると仮定しない。必要なら型・読み込み・検証も合わせて拡張する。
- 採用方式（元の先頭維持／置換）、入力動画、候補元フレーム・時刻、採用PNG、fps、composition ID、出力と選択結果を編集記録へ残す。採用PNG・編集コード・軽量記録は追跡し、候補一覧・抽出候補・出力動画はGitへ追加しない。

## 確認と投稿

- 書き出したMP4をデコードしてフレーム0と1を確認し、先頭だけが採用画像で、次のフレームが元タイムラインへ戻っていることを確認する。非可逆圧縮による画素差を編集ミスと混同しない。
- 元と同じfps・総フレーム数・尺で、音声の開始と同期が変わっていないことを確認する。冒頭を実時間で再生し、ちらつきや不自然さも確認する。
- 先頭フレームがサムネイルに採用されるかは投稿先・表示面に依存するため、全SNSでの採用を保証しない。カバー指定が使える場合は採用画像／フレームを指定する。公式サイトの既存サムネイル設定は、この工程だけでは変更しない。投稿操作は別途依頼された場合だけ行う。
