# デザインと品質監査

## 共通セーフエリア

- 左右は画面幅の5%以上、上下は画面高の5%以上を基本安全域にする。
- 縦型SNSへの再利用が予定される場合だけ、中央9:16安全域を別途設計する。指定がなければ16:9全体を使う。
- 顔、口元、手錠、武器、商品、ロゴなど重要要素の上へ字幕や帯を置かない。
- 文字は1フレーム単位で出入りさせず、原則4〜8フレームの短いeaseを使う。速報の緊張感が必要ならhard cutも使える。

## 本格ニューステロップ

- 情報階層を`局ロゴ → 速報ラベル → 主見出し → 補足 → ティッカー`の順にする。
- 局ロゴと放送時刻は生成映像へ焼き込まず、原則Remotionで後付けする。時刻は実時間APIから取得せず、`edit-manifest.json`へ`19:00`のような固定文字列で記録する。
- 速報色は赤、本文は白または濃紺を基本とし、背景とのコントラストを確保する。
- 主見出しは一度に1〜2行。長文を縮小し続けず、意味単位で短くする。
- 速報ラベルは小さく明確にし、主見出しより目立たせすぎない。
- ティッカーは主見出しを重複させず、補足情報だけを流す。
- 生成映像内の偽文字と後付け文字が競合する場合、該当領域を不透明な帯で完全に覆う。

## 小解像度で文字を潰さない

- 480pでは見出しを既定`font-weight: 700`以下、補足を`500`程度から始める。存在しない太さをブラウザに疑似生成させないよう`font-synthesis: none`を使う。
- 太字を強める前に、文字サイズ、背景コントラスト、余白、短い見出しで階層を作る。800〜900の極太と太い縁取りを同時に使わない。
- 見出しへ`0.01em`前後の字間と1.2以上の行間を確保し、`antialiased`と`geometricPrecision`で実レンダーを確認する。
- 字幕の縁取りは文字サイズの5〜6%から始める。白文字＋極太黒縁＋700以上の太字は字面を潰しやすい。
- 使用する日本語フォントとweightがレンダー環境に存在するか確認する。最終判断はStudio表示ではなく納品解像度のPNGまたはMP4で行う。

## 日本語字幕

- 正本はユーザー承認済み台本または字幕ファイル。ASRはタイミング補助に限定する。
- 原則2行以内。意味の切れ目で改行し、助詞だけを次行へ送らない。
- 16:9では下端8〜12%を基本位置とし、ティッカーがある場合はその上へ逃がす。
- 白文字、十分な黒縁または半透明背景を使い、明暗どちらの映像でも読めるようにする。
- 句読点、括弧、英数字、全角半角、固有名詞を台本と照合する。
- 字幕切替をカットと同時にする必要はない。発話開始・終了を優先する。

## フレーム監査

各オーバーレイについて次を確認する。

1. 開始1フレーム前、開始フレーム、開始後1フレーム。
2. 終了前1フレーム、終了フレーム。
3. 最長文字列が表示されるフレーム。
4. 背景が最も明るい・暗いフレーム。
5. 顔、口元、重要小道具へ最も接近するフレーム。

## 出力監査

- 映像ストリームの`nb_read_frames`が`durationInFrames`と一致し、映像尺が`durationInFrames / fps`と一致することを正本にする。AACの末尾パディングでコンテナまたは音声尺が1フレーム超長くなる場合があるため、納品先が厳密なコンテナ尺を要求するときだけ最終trim/muxを行い、再度デコード監査する。
- 解像度、fps、音声サンプルレートを納品仕様へ一致させる。
- 音声を全面差し替えた場合、入力動画音声が二重に残っていないことを確認する。
- 最終MP4を終端までデコードし、黒フレーム、フリーズ、欠落、クリックを確認する。
- 文字監査は静止画だけでなく、実時間再生で読める滞在時間も確認する。
