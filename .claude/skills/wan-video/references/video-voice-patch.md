# 動画内の声を参照するIrodori部分修復

Wan動画で演技・声を維持しながら誤読や短い台詞を直すときに使う。ローカル生成が許可される窓際族メンバーの日本語、または正典ゆめテレアナウンサーの日本語ニュースが対象。別話者のローカル生成を許可する手順ではない。

## 参照を選ぶ

- 新規発話・新規動画の声づくりは `VOICE_CAST.md` の正典参照を使う。
- 既存動画のピンポイント修復では、**そのテイクの同じ話者の声を抽出してIrodoriへ参照する方法を第一候補**にする。動画で生成された声色・演技・録音感へ寄せるためで、正典ファイルの更新ではない。
- 同じ話者だけが話す、破綻の少ない意味単位を選ぶ。複数人の声や大きなBGMが混じる区間を安易に使わない。分離が必要なら元音声も保持し、分離による変質を比較する。適切な区間がなければ正典参照へ戻す。
- モデル・seed・固有後処理は `VOICE_CAST.md` に従う。参照抽出元、時刻、SHA-256を記録する。Wan APIの声質参照15秒上限とローカルIrodoriの条件を混同しない。

## 文脈を持たせて生成する

1. 動画・音声の完成採用済みファイルは上書きせず、検証素材を `.local/` 等へ置く。
2. `ffmpeg`で参照区間と差し替え対象の音声をPCM WAVへ抽出。元のステレオ音声は維持し、参照用モノラルと区別する。
3. 正しい語句を含む**一文または自然な節全体**を `tools/irodori_speak.sh` で生成する。実際の挿入は必要部分だけ。短句単独は終止形の抑揚・余分な間・反復が出る場合があるため、比較候補として扱う。
4. ASRは誤読と切出位置の候補探しに使い、波形・試聴で語頭/語尾を確認する。日本語のword timestampsが全文ひとかたまりになる場合もあり、自動境界を音素の正解と扱わない。
5. 語句の前後に自然な無音/無声境界を取る。「公式サイト」だけで切れなければ「公式サイトでも」まで、実際に置換する意味単位を明記する。

実行例（パスと時刻は実測値へ置き換える）:

```bash
ffmpeg -i input.mp4 -ss 12.433333 -t 5.166667 \
  -vn -ac 1 -ar 48000 -c:a pcm_s16le reference_from_video.wav

tools/irodori_speak.sh \
  'このTシャツ、公式サイトでも買えるんですって！' \
  sentence_candidate.wav reference_from_video.wav 100 \
  '楽しそうな観光レポート。自然な会話の速さで、公式サイトを明瞭に話す。'
```

seed100は福ちゃんの例。他の話者へ固定しない。推定尺に任せ、指定尺へ押し込むための早口・時間伸縮・ピッチ変更を既定にしない。

やめ太郎の短文で追加発話や語尾の伸びが出る場合は[共通音声手順](../../../../tools/IRODORI_TTS.md)を参照する。正典参照では生成尺倍率0.70の設定がユーザー採用済み。ただし動画抽出参照では推定尺が変わるため、その倍率を無条件に流用しない。生成時の尺補正と完成音声の早送りを区別し、差し替え後の語尾・可視口元・後続時刻を再検証する。

## 必要部分だけ置換する

- 元と挿入音声を同じPCM16・サンプルレート・チャンネル数にそろえる。ステレオの元音声を検証の都合で全編モノラル化しない。リサンプル等は置換前の準備として記録する。
- 前後の無音を調整して、元の置換枠と挿入区間を同じサンプル数にする。後続タイムラインは動かさない。尺が合わなければ切出境界・生成文脈・候補を見直す。
- 一定ゲインでレベルを合わせてよい。背景音を含むRMSは声量の正解とは限らない。音素途中の切断やクロスフェードで不自然さを隠さない。
- [patch_pcm_audio.py](../scripts/patch_pcm_audio.py) は等尺置換・固定ゲイン・区間外PCM一致確認を行う。自動アラインメント、無音探索、ノイズ除去、声質評価はしない。クリッピングや範囲超過、上書きは拒否する。

```bash
python3 .claude/skills/wan-video/scripts/patch_pcm_audio.py \
  original_scene.wav sentence_candidate.wav patched_scene.wav \
  --target-start 1.70 --source-start 1.50 --duration 1.20 --gain-db 0.92
```

時刻は入力WAV内の相対秒。レポートのサンプルフレーム位置が丸め後の正本。完成動画のオフセットも制作記録へ残す。一定ゲインを使った場合、挿入PCMはゲイン適用後の素材と比較する。AACへ書き出す前のPCMで区間外一致を確認し、AAC再圧縮後にサンプル完全一致を要求しない。

## 比較と採用

- 元動画→修正版の比較を作り、誤読、音色・抑揚のつながり、語尾の重複/欠落、クリック、環境音の切れ、可視口元を確認する。
- 文面のASR成功、声の自然さ、リップシンクは別の評価。音声が自然でも音素長は一致しない場合がある。
- 映像/口パクが不合格なら、修復区間の画面外化など依頼範囲の編集を検討する。ユーザーが自然な可視発話を求めている場合に口元を勝手に隠さず、必要なら当該シーンの再生成を提案する。再課金は既存の承認ルールに従う。
- `post_audio_repairs` は修正元マスター・元/先時刻・理由・出力を記録する。別途 `reference_source=generated_video`、抽出元と時刻、モデル/seed/caption、切出範囲、ゲイン、PCM検証、比較評価を保存する。新しい同期方式名をAPI設定へ追加しない。
- 候補・抽出元動画・未採用音声はGit管理しない。採用した修復音声と再生成に必要な参照WAVだけをエピソードへ移す。正典 `VOICE_CAST.md` はこの処理だけでは変更しない。

## 実証した範囲

2026-09-22、東京マドギワランドの福ちゃんで検証。動画参照の単独短句は2.54秒、一文生成は4.35秒。一文から1.2秒の「公式サイトでも」を切り出し、同じ長さの元区間へ置換。前後PCM一致、速度変更なし、ASRで修正文面を確認。ユーザーが比較を「かなりいい感じ」と評価し、今後の再利用を希望した。これは一例であり、任意の台詞の完全同期や普遍的な成功率を保証しない。詳細は `03_SCRIPTS/72_tokyo_madogiwa_park/voice_patch_experiment.md`（リポジトリルート基準）。
