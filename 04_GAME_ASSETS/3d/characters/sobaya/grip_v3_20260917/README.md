# そば屋 v3：ジョッキの握り

2026-09-17。最新の顔・股・上腕・軽い挨拶を保持した、握り仕上げ用の独立モデル。

- `sobaya_grip.glb`：103クリップ付き。ジョッキ保持・移動・ゲーム用攻撃など28クリップに `MugGrip=1` を設定。挨拶を含む他のクリップは0で元の開いた手に戻る。
- `sobaya_grip.blend`：同じGLBから再読込した編集用ファイル。保持クリップ、握りモーフ、追従する正典ジョッキ、確認カメラを設定済み。
- `qa/grip_front.png`：最終GLBの拡大画像。`qa/review.json`：複数動作・42位相の追従検査。
- `report.json`：入力・出力ハッシュ、変形範囲、接触補正、不変条件。`qa/gltf_validation.json`：GLB形式検証。

## 今回の変更

元の手のメッシュ・爪・UV・肌テクスチャを使い、手ボーンの局所座標で四指を曲げた専用モーフを追加。小指から人差し指までの長さ・厚みの違いを考慮し、親指を添える。指関節に急な線形スキニングを入れず、曲がりを連続した範囲へ分散する。

正典 `props/beer_mug_v2/beer_mug.glb` の実際の持ち手を使い、接触箇所の押し戻しと局所平滑化を実施。法線も握った形へ追従する。頂点ごとの押し戻しを独立に行わず、同位置のUV境界頂点を統合した近傍場を用いる。

ジョッキソケットを握りの中心へ配置し、対象クリップでは右手へ一定の相対位置・方向で追従させる。既存の手首方向をそのまま使うため、ジョッキの傾きはその手首に従う。

元GLBのバイナリをそのまま保持して追加データを書き込む。顔、体格、ベース頂点、UV、スキニング、初期骨格、身体の103クリップは変更しない。変更するアニメーション対象は握りのモーフと `PropSocket.R` のみ。

### 四指の密着調整

ユーザー提供の握り写真を参考に、人差し指〜小指を横方向へ寄せた。各指の末端は厚みを縮めず移動し、付け根はメッシュ表面に沿う連続した重みで掌へつなぐ。親指の固定領域は移動しない。持ち手との接触補正・法線更新は密着調整後に行う。再生成処理は `tools/sobaya_grip_spacing.py`。

`report.json` の指間距離は部分的な表面の近接診断であり、指同士の全三角面の非交差証明ではない。最終形は拡大レンダリングでも確認する。

## 今回の範囲と次工程

今回の成果物は握り版のモデルと確認ページ。ゲーム本編・公式サイトの配布参照は差し替えていない。

キャラクターシートの棒立ちの構え、歩行・ダッシュ時の手の甲の向き、攻撃モーションの自然さ・迫力は、ユーザー指定どおり次工程。指を1本ずつ操作する新規ボーンは追加していない。握りと開きを切り替える専用モーフであり、任意の小道具を自動で掴む汎用リグではない。

## 検証

GLBの再読込後、保持・歩行・ダッシュ・叩きつけ・挨拶をレンダリング。保持・歩行・ダッシュ・3攻撃は各7位相で握り値とソケット追従を検査。ブラウザでも連続再生と握りの切替を確認。

接触検査は保持姿勢の手の頂点を対象に、持ち手・ガラス本体との符号付き距離を測る。これは頂点サンプルの検査であり、全三角面間の厳密な非交差証明ではない。接触部の小さな内側の皺は拡大画像で評価する。

Blenderでは、glTFの小道具座標（Y up）と再読込した小道具メッシュ（Z up）の差を、取り付け行列にX軸-90度を入れて補正する。これを省くと、ソケット原点が一致していても持ち手の方向が90度ずれ、誤った接触検査になる。Three.jsではGLB同士をそのままソケットとGripで接続する。

## 再生成・表示

リポジトリルートから実行する。

```sh
/Applications/Blender.app/Contents/MacOS/Blender -b --python tools/build_sobaya_grip.py
/Applications/Blender.app/Contents/MacOS/Blender -b --python tools/review_sobaya_grip.py
python3 tools/serve_sobaya_grip.py --port 8877
```

確認ページ: `http://127.0.0.1:8877/`。モデル2個・HTML・既存Three.jsだけを専用ディレクトリへ配置し、localhostに限定して配信する。`--stage-only` は配信中ページの素材更新用。

入力は `hazard_adopted/v3_20260917/sobaya.glb`。握り版をこの入力へ上書きしない。将来本編採用する際も、元入力と派生物を区別し、ゲームの相対symlink・manifest・Flutter実表示を合わせて検証する。

モーションの利用条件は元ライブラリを引き継ぐ。Mixamo由来を含むため、一式をCC0として扱わない。
