# そば屋 v3：歩行・ダッシュの手とジョッキ攻撃

確定した `standing_v3_20260917/sobaya_standing.glb` を入力に、歩行・ダッシュの両手と三種類の攻撃を調整した独立モデル。顔・体格・握りモーフ・スキニング・立ちポーズを保持する。

- `sobaya_motion.glb`：104クリップ。変更は下記8クリップのみ。
- `sobaya_motion.blend`：GLB再読込後の編集用ファイル。立ちポーズを選択し、確認用の正典ジョッキをソケットへ追従させる。
- `report.json`：入力・出力ハッシュ、不変条件、内向き方向、回転量、再読込照合用の骨行列。
- `qa/`：歩行・ダッシュと攻撃の位相別全身画像、左右の手首拡大、GLB検証・再読込結果。

## 歩行・ダッシュ

対象は `Adopted_Library_Walk`、`Adopted_Candidate_Chase_Run` と同系統の `Walk`、`Run`。両側の `ForeArm` と `Hand` だけを変更し、肩・上腕・胴体・脚・移動軌道・元の周期を保持する。

手首に入っていた大きなリターゲット回転を外し、元モデルの前腕と手の自然な関係を基準にする。手のひらの解剖学的な向きは既存の校正値と左右反転から求め、体の内側へ向くための回転を前腕90%、手首10%へ配分する。判定は骨の見かけの軸ではなく実際の手のひら基準。

全サンプルの内側方向との内積は歩行で約0.989以上、ダッシュで約0.851以上。追加の手首ロールは歩行約1.41度以内、ダッシュ約5.84度以内。これは補正として加えたロールであり、手首の全回転角ではない。

握りとジョッキの手への相対位置は確定版を保持し、移動時のジョッキの傾きは手の向きに従う。液体の物理シミュレーションやジョッキを常時垂直に保つ別の持ち運び姿勢は追加していない。

## 攻撃

- `Hybrid_MugPunch`：胸元から引き、踏み込んで正面へ押し込む。伸び切った肘の固定を避ける。
- `Hybrid_MugHook`：腰・胸を逆方向へ溜め、横の弧で振り、体の反対側まで振り抜く。
- `Hybrid_MugSmash`：肩口へ振りかぶり、膝・腰を沈めて斜め下へ打ち下ろす。肩が潰れる高さまで無理に上げない。

左足の約15cmの踏み込み、後足の接地、腰から胸へ分配した回転、左腕の構え、遅い溜めと速い打撃、振り抜きと回復を組み合わせる。打点を通る手の軌道には連続した速度を持たせる。始点・終点は確定立ちポーズと一致する。

元クリップの尺と、既存ゲームの `mugAttackTime` が使用する48%の打撃タイミングを保持。ダメージ・攻撃範囲・ゲーム側の移動は変更していない。独自の手付け動作であり、新収録のモーションキャプチャではない。

## 挨拶

`Greeting` は確定立ちポーズから空いている左手を上げ、同じ姿勢へ戻る2.2秒の挨拶。胴体・頭・脚・右腕は立ちポーズを維持し、右手の握りモーフも立ちポーズのチャンネルを使う。左手のひらを前へ向け、前腕にロールを分配して手首への集中を避ける。上げ下げは同じ姿勢間を滑らかに補間する。`qa/Greeting.png` に始点・上昇・保持・下降・終点を記録。

## 再生成・確認

```sh
/Applications/Blender.app/Contents/MacOS/Blender -b --python tools/build_sobaya_motion.py
/Applications/Blender.app/Contents/MacOS/Blender -b --python tools/review_sobaya_motion_v3.py
python3 tools/serve_sobaya_grip.py --port 8878
```

確認ページ：`http://127.0.0.1:8878/?pose=motion`。歩行・ダッシュ・パンチ・フック・叩きつけを選べる。1倍・0.5倍・0.25倍の速度と時刻スライダーで停止・連続再生を確認する。

原本のバイナリを保持し、選択したクリップのチャンネルだけ差し替える。立ちポーズなど96クリップは宣言も変更しない。GLBから再読込した行列、ジョッキ追従、攻撃の始終点を照合し、複数位相の描画とブラウザ表示を確認する。

確認用スナップショットでは、泡インスタンス用の `Icosphere` 原型を複製しない。これを単独の表示メッシュとしてコピーすると、足元に巨大な球が現れる。モデル本体には変更を加えない。

この版はローカル確認用のモデル。ゲーム本編・公式サイトの採用モデルは差し替えていない。将来採用するときは、本編の移動・衝突・攻撃判定・モデル間の遷移を合わせて検証する。元入力のモーション利用条件を引き継ぎ、一式をCC0として扱わない。
