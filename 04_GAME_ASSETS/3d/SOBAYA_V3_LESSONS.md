# そば屋v3：動画四面図から全身モデルを仕上げた知見

2026-09-17。次回のリアル頭身キャラクター制作・修正で参照する実例。今回の成功例と数値を記録するもので、別キャラクターへの同じ設定の成功を保証しない。

実写メンバーの顔を仕上げる場合は、[福ちゃんv3：浅い顔形状と陰影調整](FUKUCHAN_V3_LIKENESS_LESSONS.md)も参照。テクスチャ修復後に残った本人感の差を、顔の奥行きと材質の両方で改善した例。

## 有効だった制作経路

**基本キャラクターシート → Wanの一周回転動画 → 実際の映像を見て四方向を抽出 → Tripoへ全身一体入力 → Blenderで仕上げ → リグ → 最終GLBを実表示で確認。**

v2の頭部分割方式に対し、ユーザーはこのv3の全身一体モデルを良好と評価。側面・後頭部を含む連続した参照を作れたことが利点。ただし旧方式との定量的な品質比較は未実施。動画をTripoへ直接渡した実験ではない。

### 実際に採用した入力・設定

- Wan入力は `03_SCRIPTS/sobaya_turnaround_wan_20260916/character_sobaya_basic_sheet.png`。v2で使った別の正典画像ではなく基本キャラクターシートを使用。
- [実送信プロンプト](../../03_SCRIPTS/sobaya_turnaround_wan_20260916/prompt_wan3.txt)、[設定](../../03_SCRIPTS/sobaya_turnaround_wan_20260916/wan3_config.json)、[生成記録](../../03_SCRIPTS/sobaya_turnaround_wan_20260916/generation_record.json)。Wan 3.0、8秒、720P、3:4、seed 916030、単一タスク。12秒は初案で、採用は8秒。
- 実出力832×1108、30fps、8.034秒。正面0.2秒、左2.5秒、背面4.0秒、右5.6秒を無加工で抽出。**予定時刻ではなく、実際の角度を見て選定**。左右ラベルは今回の見え方の呼称で、校正されたカメラ姿勢ではない。
- Tripo入力の正本は [inputs/](characters/sobaya/wan_multiview_20260916/inputs/)。動画そのものを四面図の正本にせず、実際に採用した4枚をGit管理する。
- Tripo `P2-20260801`、quad、face_limit=15000、texture/pbr有効、texture_quality=detailed、model_seed/texture_seed=916030。[設定](characters/sobaya/wan_multiview_20260916/config.json)。実出力16102頂点・17730面、全身1メッシュ。120クレジット消費は当該タスクの記録値。Wan $0.56は当時の見積りで請求実績ではない。次回の料金・API仕様は別途確認する。

切り出しは例えば `ffmpeg -ss 0.2 -i <生成動画.mp4> -frames:v 1 front.png`。他方向も実映像で選んだ時刻を指定し、切り出し時の拡縮・トリミングで方向間の尺度を変えない。今回の秒数を別動画へ機械的に流用しない。

### 次回の動画・フレーム選び

1. キャラクターシートの複数パネルを映像に出さず、同一人物1体だけを回す。固定カメラ、全身が入る一定画角、均一な背景・照明、低モーションブラー。
2. Aポーズ、両腕と胴の隙間、指の分離、両足の接地、頭・胴・足の同時回転を指示。小道具は別生成できるよう除外する。
3. 指示どおりの完全な剛体回転になるとは限らない。今回も腕が指定より体幹に近く、方向ごとの姿勢差が残った。四枚の身長・体格・仮面・耳・髪・服・手足を画像で確認し、良い候補を選ぶ。
4. 全角度の参照があっても、生成後の輪郭や顔の一致、前傾、腕と胴の癒着、股・指のトポロジー、リグ品質は別途監査する。

## 仮面・テクスチャ・人物同一性

- **良好と判断された仮面外周を固定し、顔パーツ側を調整する。** front参照へ顔を合わせる過程で外周まで変形した案はユーザーに戻すよう指示された。輪郭の変更を顔パーツ修正へ混ぜない。
- パーツ同士の比率だけでは不十分。仮面の高さ・幅に対する顔部分の大きさ、目間隔、口幅、額の丸、鼻、赤模様を別々に測る。比較画像は仮面サイズで正規化する。目間隔だけを揃えると「顔全体が仮面に対して大きい」差が隠れる。
- 今回は目の中点を中心に顔パーツを90%へ縮小して採用。仮面外周と参照の縦横比が違うため、幅・高さを同時に厳密一致させたとは言えない。参照の顔は約100px幅で計測誤差もある。[測定・固定範囲](characters/sobaya/wan_multiview_20260916/face_scale_20260917/README.md)。90%を他モデルの既定値にしない。
- 鼻孔はfrontにないため除去。目は照明で底や反射が見える穴ではなく、奥が真っ黒に見えるデザイン。口は参照の横長形状へ。赤模様は目の縁まで届くよう調整。
- **Imagegenは塗りの修復に有効だった。** 仮面の正面albedoを平面画像に展開し、白地と赤模様を修正した採用画像を元UVへ転写した。UV全体を無条件に再生成したわけではない。島の配置・解像度・無関係な部位を保持し、形状修正はBlender側で行う。[静的仕上げ記録](characters/sobaya/wan_multiview_20260916/FINAL.md)。襟・うなじ・髪の塗りも局所補修。
- 正面だけで合格にしない。斜め左右・側面・背面・全身と、GLB書き出し後の再読込画像を確認。

## 姿勢・リグ・変形

- リグを入れるだけでは前傾は自動で直らない。今回は身長1.8m、向きを揃えた上で全体を約10度戻し、接地を再確認した。姿勢と体格・顔の局所形状変更を区別する。
- 生成モデルのスキニングは別工程。股の尖りは中央の左右腿ウェイトの急な切替を滑らかにつなぎ、骨盤の影響を補った。腕の潰れは上腕内側に残る胴体ウェイトを表面距離に基づいて分離。既存の顔と形状は維持した。[リグ・ウェイト記録](characters/sobaya/rig_v3_20260917/README.md)。
- 部位間の直線距離だけでウェイトを決めると、近接する腕と胴へ漏れやすい。表面距離、UV継ぎ目の同位置点、非連結部分を考慮する。補正範囲を広げ過ぎた案は袖・脇の伸びを悪化させた。
- 頂点グループを削除しながら走査するときは、可変のVertexGroupElement参照ではなく整数group IDを先に退避。今回の試作で削除順によりスパイクが出た。
- DQ/Preserve Volumeだけで軸の向きや誤ウェイトは直らない。修正は不変のベースへ一度だけ適用し、累積適用を避ける。最大4影響・正規化を検証する。

## 手の表裏・挨拶での失敗と採用解

- 肘→手首の方向が合っていても、手のひら方向の校正にはならない。前腕軸回りのrollと親指方向も必要。
- **甲を手のひらと取り違えた画像判定があった。** 右手を正面に向けた場合は親指が画面右に来ること、手のひらのくぼみ・しわ、爪・甲を拡大して確認する。鏡像や背面視点では左右条件が変わるため、撮影方向を先に固定する。自分で設定した法線の数値だけでは表裏の正しさを証明できない。
- 旧Greetingに前腕・手首の計90度補正を足し、終盤に戻す方式は自然さを満たさず置換。元の下降時の回転と追加補正の戻しが重なった。上げ切った1姿勢だけを成功判定にしない。
- 元の採用Greetingはv2制作時のPython/Blenderによる3秒の独自動作。同名のLibrary_Greetingと混同しない。最新版は**新規に作った2.2秒の「よっ」**。[正本と再生成](motions/casual_greeting_20260917/README.md)。福ちゃんも同時更新。両者のneutral→raisedを同じ経路で戻し、短い保持と小さな会釈を付けた。そば屋の手のひら基準は再校正済み。
- そば屋の指には個別骨がなく、握りは別工程。指リグ、曲げた形、ジョッキ持ち手との接触位置をまとめて仕上げる。福ちゃんには既存の指リグがあり、挨拶時の開きを調整できる。

## 検証・再現で外せないこと

- Python/MCPで制作しても**画像確認を省略しない**。正面の保持姿勢だけでなく、上げ始め・中間・下ろす途中・終端を同じ視点で比較し、連続再生と斜め視点も確認する。ユーザーがComputerを指定した背景は、この目視工程の欠落を防ぐためだった。
- Blenderの終了コード0だけで成功としない。Traceback、完了マーカー、成果物の有無、最終GLBまで確認。
- glTF読込は**読込前にfpsを設定**する。24fpsで読み込んだキーを後から30fpsへ変えると、同じフレーム番号でも時刻が違う。今回の比較で発見した。秒数または同一fpsで比較する。
- 一つのクリップだけ変えるときは、メッシュ全体の再書き出しを避けてアニメーション差し替えも可能。ノード名は一意とは限らず、福ちゃんではHead骨とHeadメッシュが同名。skin jointかmeshかを区別して対応させる。
- ジオメトリ・UV・材質・骨格・ウェイト・他クリップが変更範囲外なら、数値／バイト不変を検証。見た目の検証とは別に必要。
- GLB更新後のFlutterはフル再ビルド。hot reloadだけでは変換済みアセットが更新されない。新しいapp URIでMCPへ接続し、連続再生を確認。公式サイトはURL世代更新と、配信GLBのハッシュ照合を行う。
