# 赤坂ステージ（昼・夜）

採用した `app/design/stage_concepts/D_akasaka_prompt.txt` の方向性を、Flutter Sceneで動く3D背景にしたもの。実在街区の測量再現ではなく、赤坂の飲食店街と東京タワーを組み合わせたゲーム用の構成。

- `akasaka.glb`: 38メッシュ（33マテリアル、車の走行グループ6本を含む）の静的背景、65,220三角形。東京タワーと公園、鉄骨と支えビル、道路網（大通り・路地・車線・横断歩道・歩道）、街灯、首都高の高架、区画割りした街並み、笠木・ライトアップ帯、屋上設備・屋上広告・高層ビルの大型看板12枠・航空障害灯、外周のスカイラインを含む。車は `traffic_zpos` / `traffic_zneg` / `traffic_xpos` / `traffic_xneg` / `traffic_hwy_xpos` / `traffic_hwy_xneg` の6ノードで、各ノードは周期（24・30・27単位）で繰り返す配置。ゲームがノードを動かして走らせる。
- PNG: 手続き生成と採用したImagegen素材を組み合わせたテクスチャ（`ad_yumemin.png` はリポジトリ内の正典 `characters/Yumemin.jpg` を合成）。外装6種（`facade_0`〜`5`、4×8単位で反復）は昼の窓の色、`facade_*_emit.png` は点灯した窓だけの発光マップ。ほかに鋼材の錆止め塗装、アスファルト、歩道、遠景（`skyline` / `skyline_emit`）、車のアトラス（車体2色・ヘッドライト・テールランプ）、縦看板6種、屋上広告2種（`ACCIDENCHUA`、「安全第一」）、ゆめみんの看板（`ad_yumemin`）、空き枠用の「広告募集中」（`ad_recruit`）、協賛広告のアトラス（`ad_sponsors`）。
- 時間帯（昼・夜）による発光の強さはGLBに焼き込まず、ゲーム側（`app/lib/stage_lighting.dart`）でマテリアルごとに設定する。
- 再生成: リポジトリルートで Pillow入りPythonから `app/tool/build_akasaka_textures.py`、`prepare_stage_surfaces.py`（同じtoolディレクトリ、Pillow/NumPyが必要）、続いて Blender `-b -P app/tool/build_akasaka_stage.py`。最後に `uv run --with pillow python app/tool/optimize_stage_textures.py` と `python3 app/tool/audit_stage_asset.py` を実行する。
- ゲームは `assets/models/akasaka.glb` の相対symlinkで参照。GLTF読込時の座標系に合わせ、シーン側でY軸180度回転する。
- 背景には衝突・転落判定を追加しない。空と霞はFlutter SceneのSkybox / Fogで描画。


## 表面品質の改善（2026-10-20）

- `source_imagegen/`: built-in image_genの採用原画5枚、外壁の生成入力3枚、実際のプロンプト。外壁0/3/4は窓・階の配置を保ったタイル外壁／ガラスカーテンウォール／集合住宅。steelは赤錆止め塗装と擦り傷、asphaltは骨材と微細な補修跡。
- `prepare_stage_surfaces.py`は原画の通常縮小とPBRデータマップ生成を行う。色画像の描き直しはしない。窓と壁の粗さ・金属度を分けたMRマップ6枚、鉄骨と路面のMR/浅い法線マップを追加。法線は画像輝度からの控えめな近似で、実測スキャンではない。夜の発光は従来の点灯部屋を維持し、窓内部へ制限。
- 建物の外形・衝突・鉄骨寸法・マテリアルによるバッチ分割は維持。高架の路面もstreet材質へ変更。全ステージ材質を片面描画にし、裏面の不要なピクセル処理を削減。
- 39プリミティブ、71,872三角形を維持。GLBは約6.70→9.91MB。画像をRGBA8へ展開したベースレベル概算は36.51→44.26MiB（mipmap・ドライバ管理分を除く）。追加の昼夜環境マップは128px/面の静的キューブ各1MiB程度＋入力画像。画像はすべて長辺1024px以下。`tool/audit_stage_asset.py`で上限を検査。
- ガラスの映り込みは、生成画像にある静的模様＋昼夜の小さな環境マップによる視点依存の光沢。周囲のゲームオブジェクトや人物を正確に映すリアルタイム反射ではない。追加の反射カメラ・街の再描画・透明ガラスの重ね描きはない。
- 共通のスタジオ照明はアイテム選択プレビューに保持し、ステージには昼夜の屋外照明を使う。これにより商品プレビューと屋外の材質感を分ける。

## 配布テクスチャ解像度の最適化（2026-10-20）

上記の44.26MiBは高解像度版の記録。解像度最適化時点の配布GLBは13.13MiB（RGBA8ベースレベル、約70%削減）、7.15MB。この段階では形状は同一。元PNG、Imagegen原画、プロンプトは変更せず保持し、Blenderで高解像度GLBを再生成できる。最適化ツールはGLB内の画像とバッファ位置のみを書き換える。

- 遠景外壁: 512×1024 → 256×512。近い支持ビルにも使うfacade_0の色画像は512×1024を維持。
- 外壁発光: 256×512、粗さ・金属度: 128×256。
- 鉄骨: 1024×256 → 512×128。路面: 512×512 → 256×256。
- 縦看板: 256×768 → 128×384。広告: 1024×384 → 512×192。小さな車アトラス・遠景・歩道は維持。

基準はiPhone 18 Pro横2622×1206px、縦FOV約39.5度、固定距離約11mのゲームカメラ。外壁は4m×8mの反復で、奥の建物ほど1タイルの画面占有が小さい。最寄りの外壁は単純な一律縮小から除外した。画質設定は従来どおりで、この最適化は標準・軽量の両方に適用。環境キューブ、描画解像度、影のサイズは変更しない。展開量は理論値で、実機のGPUメモリやFPSの測定値ではない。

## タワーと公園の再構成（2026-10-20）

高さの基準は200m=14シーン単位。鉄骨を支えるビルの屋上を200m、東京タワーの先端を333m、展望台を150m/250mとした。従来のタワーだけの縦0.78倍処理を撤去。一般ビルは35〜70m、左側・外周のアクセントは90〜140m、公園の周辺は15〜40m。奥のスカイラインも低くし、全ビルよりタワーが高い。道路幅・街区・人物との縮尺はゲームの構図に合わせたもので、実在街区の測量再現ではない。

タワー中心を(15,-46)へ配置し、約211×234m相当の公園を確保。芝生・広場・十字と外周の園路・低ポリゴン樹木20本・足元灯8基を追加。周辺の建物生成を除外し、高架はz=-64へ移してタワーの背後を通す。低いビルの縦看板は建物高に合わせて縮小。公園は既存の舗装材＋単色の芝生/樹木材をバッチ化し、追加テクスチャ・透明葉・動的ライトは使わない。

カメラは縦FOV 0.78rad（約44.7度）、ゲーム中の注視点y=2.9。正面のiPhone横画面で先端とHUDの間に余白を確保し、足元と公園を見せる。鉄骨の寸法、操作、当たり判定は維持。遠くへ大きく旋回するとタワーが画面端へ移る通常の透視投影で、画面内への固定表示はしない。

最終GLBは6,924,244 bytes、39プリミティブ、68,752三角形（以前71,872から約4.3%減）。テクスチャは13.13MiBを維持。監査は形状の上限・タワー先端の高さ・ビルとの高低差・公園の存在を確認する。

## 協賛広告の追加手順（2026-10-22）

協賛広告は `source_ads/ads.json` の1要素が1枚。左に原画（330px四方に縮小）、右に文字を置く共通フォーマット。

1. 原画を `source_ads/` に置く（正方形、330px以上）。
2. `ads.json` に `name`・`art`・`background`・`frame`・`lines`（文字・大きさ・中心x/y・色、1024×384基準）を足す。既存の要素をコピーして画像名と文字だけ変えればよい。
3. `build_akasaka_stage.py` の `BILLBOARDS` で、差し替える枠の広告名を新しい `name` にする。
4. 冒頭の再生成手順を流す。

全員が1枚のアトラス `ad_sponsors.png`（1024×384のセルを8行ずつの列に並べる）と1マテリアルを共有するため、増やしてもプリミティブは増えない。配布時は1セル256×96、1枚約0.094MiB。12枠すべてを協賛広告にしても約1.1MiBで、上限14MiBまで余裕がある。
