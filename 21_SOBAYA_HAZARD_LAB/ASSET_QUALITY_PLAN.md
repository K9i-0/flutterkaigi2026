# そば屋ハザード — アセット品質改善方針

2026-09-05。ユーザーから指摘された肩の崩れ・顔・握り・ガラス／液体について、現在の実装とTripo公式v3 APIを調査した記録。以下は次の修正方針であり、修正済みの報告ではない。調査に伴う生成API実行・クレジット消費はなし。

## 1. 腕を上げたときの崩れ

現在の`tools/build_sobaya_rig.py`は自動ウェイトを出発点に座標ベースで胴体を補正する初版。Shoulder.L/Rはあるが、アニメーションでは鎖骨を動かさずUpperArmに大きな回転を集中させている。肩・袖の補正モーフもない。前回のウェイト合計・ループ・再生検査の合格は、変形品質の合格を意味しない。

修正順序:

1. 元の四角面を保持した`sobaya_source.blend`で肩・脇・肘・指の面とパーツ境界を確認する。
2. 肩関節と鎖骨の位置・回転分担を修正。肩・上腕・胴体のウェイトを部位ごとに調整し、袖が胸や腕に引きずられるのを抑える。
3. それでも折れる／潰れる部分だけ関節向けに面を張り直す（局所リトポロジー）。元モデルからテクスチャを焼き直す。ポリゴンの一律増加は解決策にしない。
4. 高い腕上げに必要なら肩・脇の補正モーフを追加。クリップの補正カーブをglTFへベイクするか、ゲーム側で骨角度からモーフ値を駆動する。
5. 服と身体の干渉を確認し、見えない身体面の削除や袖の分離を必要箇所へ適用する。

Flutter Scene 0.23.0のスキニングは4ジョイントの行列加重和。BlenderだけでPreserve VolumeやCorrective Smoothを有効にしても、その処理がゲームへ自動移植されるわけではない。glTFに渡せる骨・ウェイト・モーフで解決し、Blender→GLB→Flutterの順に同じ角度で確認する。同梱実装はスキニング前のモーフにも対応（同時評価は最大8ターゲット）。

次の判定は肩0/45/90/135/160度、肘曲げ、前腕ひねり、全モーションの正面／側面／背面。袖の大きな伸び・穴・面の反転・身体の突き抜けが残る段階を「完成」としない。

## 2. Tripoで複数画像を渡せるか

公式v3のPシリーズ・マルチビューAPIは`P2-20260801`を明記している。

- `POST /v3/generation/multiview-to-model`
- `inputs`に`front` / `left` / `back` / `right`を指定。
- 正面必須、合計2〜4方向。省略する方向はview-key形式なら配列に入れない。
- 同じ対象・一貫した照明の画像が必要。三面図を1枚のコラージュとして入力するより、方向別の画像ファイルに分けて渡す。
- 画像生成側でポーズ、手指、衣装、髪、身長、投影、画角をそろえる。全身の大きさをそろえた、腕と胴／脚同士が離れたAポーズを制作上の標準とする。左右非対称のキャラクターは4方向を用意する。
- `quad:true`は出力形式の指定であり、関節の変形品質の保証ではない。既存のそば屋もquad指定で生成済み。

送信形式の例（実行していない）:

```json
{
  "model": "P2-20260801",
  "inputs": [
    {"front": "<front_file_token>"},
    {"left": "<left_file_token>"},
    {"back": "<back_file_token>"},
    {"right": "<right_file_token>"}
  ],
  "quad": true,
  "texture": true,
  "pbr": true,
  "texture_quality": "detailed"
}
```

現行`tools/tripo_generate.py`は単画像のimage-to-model専用。複数画像のアップロード記録、画像別ハッシュ、重複課金防止、multiviewエンドポイントへの対応は実装が必要。既存runを上書きせず、新runで比較する。フリークレジットでの単画像P2詳細生成は成功実績があるが、マルチビューでの当該アカウント実行可否・消費量は未確認。Studioのプラン条件をAPIへそのまま当てはめない。

出典: [Tripo P Series Multiview](https://developers.tripo3d.ai/en/docs/generation-multiview-to-model/p)。

## 3. 顔アップと仮面の黒い目

P2マルチビューの公開入力は方向別の全体像用であり、追加の`face_detail`や顔の位置指定パラメータは確認できなかった。全身の背面枠に顔アップを入れない。

Texture APIは単一の参照画像、またはfront/left/back/rightの4画像を受け取る。`part_names`による分割済みパーツの指定もある。ただし任意の顔アップを渡すだけで全身モデルの顔へ正確に貼られる仕様ではない。P2原型のテクスチャ再生成・パーツ指定の組み合わせは実行検証が必要。

制作方針:

- 顔の正典アップを別に保持し、Imagegenで全身参照を作る時点でも顔の同一性を維持する。
- 顔／仮面を独立した編集対象・UV領域にする。全身4Kのままでも、顔に割くUV面積が小さければ局所の解像度は不足する。
- 仮面の目の奥が空洞に見える問題は、黒い内張りを穴の少し奥に配置し、漏れを防ぐ局所修正が第一候補。黒は不透明・高粗さ。必要ならUnlitで安定した黒にする。左右・斜め・背面からの見え方も確認する。
- 眼孔の縁や額の不要な凹凸は局所スカルプトと法線マップの修正対象。ノーマルを弱めるだけでは実際の穴は塞がらない。
- そば屋の仮面は単純な形なので、必要なら仮面だけをきれいな別メッシュとして作り直せる。全身の再生成は最初の手段にしない。

出典: [Tripo Texture API](https://developers.tripo3d.ai/en/docs/models-texture)。

## 4. ジョッキを握る手

現実装は手首のひねりと各指へ共通の曲げ角を与える方式。ソケットとGripの一致は小道具の位置合わせであり、指と取っ手が接触している保証ではない。

ジョッキの取っ手寸法を先に確定し、それに合わせた専用の握りポーズを作る。親指、各指の付け根・中間・末端を個別調整し、掌と指が取っ手を挟む形にする。指の元形状が崩れていれば手だけ局所修正する。上腕・肘はIK等で制作し、ゲームへはベイクした骨の動きとして渡せる。握りは乾杯・攻撃で共通に維持し、持ち上げ／振りかぶり／接触／戻しの全区間で手から離れたり貫通したりしないかを見る。

## 5. ジョッキ専用モデルとFlutter処理

現在のモデルはガラスのalpha=0.10、metallic=0.08、ビールは不透明の円柱。泡は球の組み合わせで全パーツを1メッシュに結合している。光の屈折・液面の傾き・泡の細かい質感は未実装。ユーザーが重視する小道具としては作り込みが足りない。

次版は`BeerMugRoot`の下にGlassBody／Handle／BeerVolume／LiquidSurface／Foam／Gripを分け、共有小道具のままゲーム側から材質と液面を調整可能にする。寸法が重要な回転体と取っ手はBlenderのパラメトリック生成を継続し、Tripoを使う必要はない。

| 対象 | 表現の方針 |
| --- | --- |
| ガラス | 実厚のある底・縁・取っ手、低粗さ、非金属、Transmission＋IOR＋厚み。屈折と環境反射で輪郭を出す |
| ビール | 琥珀色の光吸収、透過、深さによる色の変化。体積と表面を分離 |
| 液面 | ワールド上方向を基準に傾斜補正し、加速度へ減衰する揺れを追加。容量・内壁との整合も維持 |
| 泡 | 不透明寄り、細かな凹凸と粗さ、液面と一緒に移動する泡の厚みと縁 |
| 細部 | 少量の上昇する気泡、必要なら結露。画面上のサイズで省略する |
| 照明 | ガラスに映り込む明暗がある環境IBL。ローカル反射プローブを必要時だけ更新 |

Flutter Scene 0.23.0には標準PBRの`transmission` / `ior` / `thickness` / `attenuationColor` / `attenuationDistance`と、glTF拡張の読み込みがある。まず標準材質を正しく使用する。透明描画は奥から手前へ並べ、重なるscene-color参照では描画先更新を挟む実装もある。ただし曲面・内外壁・液体を重ねた物理的に正確な多重屈折を保証するものではない。

専用`BeerMugComponent`で装備・液量・揺れ・近遠品質を管理する。標準材質で内外壁とビールの重なりが破綻する場合、scene color/depthを読む専用`.fmat`でガラスとビールの見え方をまとめる。毎フレームの完全な流体計算や動的な6面反射キャプチャは最初から採用しない。

判定は暗い背景／明るい背景／模様付き背景、空／半分／満杯、静止／乾杯／振り下ろし、1個／複数個、ゲームカメラ／手元アップ。背景が屈折して見えること、金属やオレンジ色の固体に見えないこと、液面が容器から飛び出さないこと、GPU負荷を含む実機測定で近遠品質を決めることを確認する。

実装確認箇所（インストール済みflutter_scene 0.23.0）:

- `lib/src/material/physically_based_material.dart`
- `lib/src/runtime_importer/material_builder.dart`
- `assets/materials/physical_transmission.fmat`
- `lib/src/scene_encoder.dart`
- `shaders/flutter_scene_skinned_body.glsl` / `flutter_scene_morph.glsl`

参考: [Flutter Scene公式](https://github.com/bdero/flutter_scene)、[Blender glTFのアニメーション／材質出力](https://docs.blender.org/manual/en/5.3/addons/scene_gltf2.html)。

## 作業の優先順

既存そば屋の肩と握りを直す → 仮面の黒い内張りと形を直す → ジョッキの専用表現を作る → 福ちゃん・たこさん・やめ太郎を方向別参照で生成する。

これで、同じリグ不備を他メンバーへ複製する前に変形と持ち物の基準を確定できる。今あるそば屋は検証素材として維持し、改善版と同じカメラ・同じ姿勢で比較する。
