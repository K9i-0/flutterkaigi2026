# パフォーマンス検証（2026-10-21）

目標は現環境で60fps。標準設定の最終プレイ計測は56.54〜60.00fps相当、
全条件のフレーム間隔p95は16.667〜16.668ms。大半は60fps相当だが、
完全な60fps固定は未達。最も良い試行だけを結果として選んでいない。

## 条件と指標

- iPhone 18 Proシミュレーター、iOS 27.0、2622×1206、Flutter 3.47.2 debug。
- 標準: 3D長辺1440px（scale約0.5492）、FXAA、影1カスケード・距離24。
  車の影生成を省略。反射・表面凹凸・夜景ブルームは有効。UIは端末解像度。
- 120フレーム準備、360フレーム収集。seed 1、既定のゲームバランス。
- `final-play.json`: ゲームを1/60秒刻みで進め、移動・落下・接触・アニメーションを動かす。
  計測途中でアイテムが枯れないよう6〜16秒区間を繰り返す。カメラは正面。
- `final-orbit.json`: 同じプレイに左右60度の連続カメラ回転を加える。
- `submittedFps`はFlutter FrameTimingのvsyncStart間隔から算出。
  GPU時間・実ディスプレイへの提示FPSではなく、実機profile測定でもない。
- 同じMacで別のシミュレーターアプリ等も稼働。無関係なアプリは停止していない。
  試行間の揺れがあり、サブfpsの差を改善率として断定しない。

## 切り分けと採用理由

- 変更前の固定スナップショットは約25.80fps、背景非表示で53.72fps。
  キャラクターのみ非表示は27.79fps。背景側を優先した。
- 車は6つの車列メッシュをまとめて移動している。
  背景の不要面削減後、車停止26.40／移動26.49／非表示27.03fps。
  この条件では移動自体が主因ではなく、車の台数・動きを残した。
- 高画質相当のままでは処理整理後もプレイ29.23fps（`active-quality-ablation.json`）。
  背景描画の画素数・アンチエイリアス・遠景影の組み合わせが大きい。
- HUDを毎フレーム再構築せず、表示値の変更時に更新。3DをRepaintBoundaryへ分離。
  未使用モデルをライブシーングラフから外し、形状・動作を保持したまま再利用する。
- 骨行列がfloat32で完全に一致する場合のみ、GPU転送済みのポーズを再利用。
  native CPUサンプルでは骨テクスチャ転送時のMetalコマンドキュー待ちが見られた。
  サンプル待ち時間をGPU実行時間としては扱わない。
- 背景は白線の上面、車体の見える面、ライトの外向き面だけを残す。
  65,220→45,254三角形（30.6%減）、38プリミティブを維持。
  GLB6,637,600→5,240,224 bytes、RGBA8ベース換算12.76MiBは同じ。
- ブルーム無効化では夜景のbuild/raster時間は下がったが、平均送出fpsの改善は
  一貫しなかった（`bloom-off-play.json`）。標準ではブルームを残した。
- おだてつは形状・画素を維持する整理のみ採用。20.35→14.15MB。
  3D形状削減の候補は約1.3%しか減らず不採用。
  モデル差し替え前後のfps差は小さく、読み込み資産量の削減をFPS改善と混同しない。

変更前のbaselineは静止、最終結果は実際のプレイなので、そのまま倍率を算出しない。
`trial-play.json`は最終採用前の約0.55倍描画の試行、`before-model-play.json`は
おだてつ派生版を組み込む前。最終の判定には`final-play.json`を使う。

## 再現

Dart MCPでこのアプリをdebug起動し、得たVM Service WebSocket URIを指定する。
コード変更後はhot restartで拡張コールバックを更新する。
GLB変更後は完全に再ビルドして、同梱ファイルのSHA256一致を確認する。

```sh
uv run --with websockets python app/tool/perf_probe.py VM_URI /tmp/play.json final
uv run --with websockets python app/tool/perf_probe.py VM_URI /tmp/orbit.json orbit
uv run --with websockets python app/tool/perf_probe.py VM_URI /tmp/traffic.json traffic
```

計測ツールは画質設定を永続化しない。完了後はhot restartか通常のstartで戻る。
過去ログの画質はラベルだけでなく`renderer`の実効値を参照する。

検証: flutter analyze問題なし、flutter test 26件成功、実行時エラーなし。
3人×昼夜、カメラ回転、標準→高画質→標準の実UI操作と保存を確認。
高画質はscale 1/MSAA/3カスケード/距離85へ戻り、標準で元の軽量設定へ戻る。
`standard-day.png`・`high-day.png`・`standard-night.png`は実アプリの確認画像。
キャラクター・落下物の形状とアニメーションを削減せず、画質差は3Dの解像度・
輪郭処理と遠景影に限定。完全固定60fpsは未達。実機での発熱・長時間性能は未確認。
