# ゆめみ採用試験（試作）

横画面固定、20秒のFlutter Scene製3Dキャッチゲーム。ゆめみの採用試験で、受験者が赤坂の高層ビルの間に架かった鉄骨を渡らされるというネタ。鉄骨編ではキャラクターと時間帯（昼・夜）を選び、落ちてくる「あたり」だけを集める。従来の屋上・面移動版も選択できる。表示名は2026-10-20に「蕎麦屋」から改名。同日、ディレクトリを `26_SOBAYA_BEER_RAIN` から `26_YUMEMI_RECRUIT_EXAM` に、Dartパッケージ名を `sobaya_beer_rain` から `yumemi_recruit_exam` に変更。アプリIDも変更：Android `jp.madogiwa.yumemi_recruit_exam`、iOS/macOS `jp.madogiwa.yumemiRecruitExam`（製品名 `yumemi_recruit_exam`）。端末上は旧アプリと別扱いになり、旧アプリの保存設定は引き継がない。

## 遊び方

- スタート時の持ち方を中立にして、端末を小さく前後左右に傾けて移動。約14度で最大速度。
- 画面を左右にスワイプしてカメラを回転（鉄骨編は30度、面移動版は45度ずつ）。回転中も画面を基準に移動方向を変換する。画面上の操作ボタン・パッドはない。
- 缶の影と着地点の輪へ先回りすると自動キャッチ。ビールは100点、連続キャッチで最大200点。発泡酒は−200点でコンボが切れる。
- ビールを逃すとコンボが切れる。発泡酒を避けても減点されない。
- 一時停止から再開すると持ち方を再調整する。センサーが使えないシミュレーターではキーボードの矢印キーで移動する（画面には操作UIを出さない）。
- 「配置」を押して次のプレイの配置seedを変更できる。

## 素材

窓際スーパーつらいは `03_SCRIPTS/00_TEMPLATES/props/product_super_try.png` を正典として3D缶へ投影。窓際ライトと発泡酒「つらめ」は今回限りの仮デザイン。仮の識別手掛かりとして発泡酒には紫帯を付けている。

モデルは `assets/models/` から共有資産への相対symlink。そば屋は `04_GAME_ASSETS/3d/hazard_rebuild/locomotion_v1/sobaya.glb` のIdle/Walk/Runを再利用し、体型や顔は変更していない。移動速度に歩行・走行モーションを同期する。効果音は既存の `25_SOBAYA_IPPAI/assets/audio/` を参照。

## 自動操作と撮影

Dart MCPでdebug起動し、App URIへMarionetteを接続する。

- `madogiwa.inspectCatch`: phase、時刻、座標、カメラ角、得点、落下缶、キャッチ履歴、センサー有無。
- `madogiwa.catchAction`: `action=start` で停止状態のラウンド開始。
- `action=step, seconds=0..25, x=-1..1, y=-1..1`: 60Hzで入力を進めて停止。xは画面右、yは画面奥。
- `action=rotate, direction=1|-1`、`action=pause|resume`。
- `action=demo`: 撮影用入力コントローラ。移動入力とカメラ操作だけを供給し、通常の衝突・得点計算を通す。実機の傾きセンサー収録ではない。最初の発泡酒にも向かうため減点を確認できる。

XcodeBuildMCP `record_sim_video` で開始→ `action=demo` →約25秒後に停止。`qa/playthrough.mp4` がローカルの納品動画。動画はゲーム内組み込み用資産ではないためGit管理しない。

## 左右移動版（2026-10-02追加）

起動時は左右移動版。開始・結果画面の切替ボタンで従来の面移動版も遊べる。

- 移動はX軸の一本道。前後入力を無視し、カメラを動かしても左右操作は逆転しない。
- カメラは30度ずつ、正面から左右60度まで。缶はカメラへ正対せず、左右70〜110度の固有の向きを保って落ちる。
- 左右版の缶は表140度にだけ識別ラベルを付け、残りは3種共通の銀色。裏から紫帯を見て即判別することを防ぐ。正典缶の表画像は従来と同じ。
- そば屋は共有GLBのWalkを速度同期で連続再生し、立ち止まるとIdleへ遷移。最大速度2.6。
- 専用GLBは `tool/build_cans.py -- --lane` をBlenderで実行して生成。既存の面移動用GLBは維持する。
- 自動操作は `madogiwa.catchAction` の `action=start|demo, mode=lane|plane`。撮影用コントローラは対象の向きへカメラ入力を供給する（人間の目視判定を再現するAIではない）。
- 新しいプレイ動画は `qa/lane_playthrough.mp4`（シミュレーター実画面、入力自動供給、無音）。

追加検証: 一本道のZ固定、前後入力無視、カメラ上限、缶の向きの独立性、左右版完走を含む計7テスト。iOSシミュレーターで正面の側面表示→斜め視点の表ラベル表示を確認。実機の傾き操作感は引き続き未検証。

## 鉄骨編の舞台

左右版を高所の鉄骨渡りへ変更。移動可能範囲に沿った幅0.95のI字鉄骨を、両端の支柱に架ける。広い床を撤去し、足場のない前後には移動できない理由を地形で示す。両端にはストッパーと警戒模様、天面にはボルトと黄色い縁線。下方約17単位に道路と建物を置き、見下ろすカメラで高さを見せる。

## ゲームバランス調整（debugビルド）

右上のスライダー形アイコンから「バランス調整 / DEBUG」を開く。編集中は一時停止し、キャンセルなら元の状態へ戻る。「保存して最初から試す」は設定とseedを端末内へ保存して、新しいラウンドを開始する。再起動後も保持。「標準」で既定値に戻せる（seedは独立）。releaseビルドには調整ボタンを表示しない。

調整項目は14項目：制限時間、出現間隔、落下時間、移動応答、面移動版のキャッチ半径、発泡酒割合、ビール基本点、発泡酒減点、コンボ加点、カメラ回転幅、カメラ上限、缶の向きの最小・最大角、センサー感度。カメラ角は鉄骨編用。キャッチ半径は面移動版のみ、鉄骨編の速度・半径はキャラクター固有値を使う。それ以外は両モードに適用する。旧JSONの`moveSpeed`は読み込み互換のため保持するが、移動には使わない。発泡酒割合は0〜1（0.25=25%）、缶数に応じて切り捨てた本数を均等に配分する。

落下時間を長くすると判断の猶予が増え、出現間隔を短くすると忙しくなる。面移動版でキャッチ半径を大きくすると取りやすいが、発泡酒も拾いやすくなる。缶の角度を正面から遠ざけると見回す必要が増える。足場と移動制限は固定で、転落要素はない。

「標準・やさしい・難しい」の3プリセット。同じseedと設定で配置を再現できる。設定JSONをコピーして比較条件を記録し、貼り付けて「JSONを読み込み」→適用で復元する。JSONで省略した設定は標準値で補完する。値域外、非数値、未知のキー、最小角>最大角は拒否する。

```json
{"seed":123,"balance":{"roundSeconds":20,"spawnInterval":1.2,"fallSeconds":4,"badRatio":0.25,"catchRadius":0.8}}
```

Marionetteからは `madogiwa.catchAction` に `action=configure`、`json`（balanceオブジェクトのみのJSON文字列）、任意の`seed`を渡す。こちらは現在値への部分更新。保存・再スタート後に停止し、`step`や`resume`で検証できる。`madogiwa.inspectCatch`は適用中のbalance、seed、総缶数も返す。

描画は16枠のプールで、各枠に缶3種を用意。最大密度でも見えている缶の種類と衝突判定を一致させる。出現は全缶が制限時間内に落ち切る時刻までで打ち切る。

## キャラクター別ルール・落下モデル（2026-10-20）

鉄骨編の初期選択は **CTOおだてつ／ノーマル**。

| キャラ | 難易度 | あたり | はずれ | 出現間隔 | 落下時間 | はずれ比率 |
| --- | --- | --- | --- | --- | --- | --- |
| 福ギュン | イージー | ゆめみん | やめ太郎 | 基準×1.45 | 基準×1.35 | 基準×0.6 |
| CTOおだてつ | ノーマル | ちくわ | 毒ちくわ | 基準値 | 基準値 | 基準値 |

基準は既存のバランス調整値。出現間隔は 0.5〜4.5 秒、落下時間は 1〜6 秒、
比率は 0〜1 に制限し、最大16枠の描画プールに収める。移動速度とキャッチ半径は
既存キャラ値を維持。ラウンド開始時のキャラを固定し、プレイ中の選択変更は不可。
面移動版は従来のそば屋・缶のルールを維持する。

選択画面は明るい紙色の背景、縦並びのキャラ一覧、あたり／はずれの3D表示。
そば屋のビールは2銘柄を同時表示する。`DropModels` が選択画面とゲーム中の
共通モデルを作り、ちくわの `Wiggle` とやめ太郎の `Idle` を既存のリグで再生する。
画像に置き換えたプレビューではない。

- ちくわ: `04_GAME_ASSETS/3d/props/chikuwa/game_v3/`（各32,320三角形、9ボーン）
- ゆめみん: `04_GAME_ASSETS/3d/characters/yumemin/color_20260919/yumemin.glb`
- やめ太郎: `04_GAME_ASSETS/3d/characters/yametaro/rig_nose_v3/yametaro.glb`

すべて `assets/models/` の相対 symlink で参照し、build hook で変換。

`badRatio`、`dropKinds`、`visibleDropModels` を追加。`caught` / `bad` 判定は各モデルの

## ステージの質感・画質設定（2026-10-20）

Imagegenで外壁3種・鉄骨・アスファルトを制作。512〜1024pxへ縮小して採用し、窓と壁の粗さを分離した材質マップ、鉄骨と路面の浅い法線マップを追加した。窓の光沢には昼夜の静的な街／空の環境マップを使い、視点で明暗が変わる。周囲の人物や車を正確に映す鏡面反射ではない。反射用の街の再描画は行わない。屋外の照明は選択画面の商品用スタジオ照明から分離した。夜は手前の照明を補い、タワーの白飛びとブルームを抑えている。

選択画面とプレイ中のモニターアイコンから「画質設定」を開く。標準／軽量と、太陽の影・追加の反射・表面の凹凸・夜景の光のにじみ・高精細描画を個別に変更できる。設定は端末に保存。プレイ中のダイアログ表示はゲームを一時停止し、閉じると元の状態へ戻る。

軽量は影・追加反射・法線・ブルームを無効にし、3Dの解像度を縦横80%（画素数64%）にする。UIの描画解像度とゲームのルールは変えない。テクスチャ自体は共通で読み込むため、軽量設定は主に描画処理を軽くするもので、読込メモリを解放する設定ではない。

解像度最適化時は39プリミティブ／71,872三角形を維持（後述のタワー改修後は68,752三角形）。配布GLBの画像はiPhone横表示向けに用途別に縮小し、RGBA8ベースレベル換算44.26→13.13MiB（約70%減、mipmap・ドライバ管理分は別）。近い支持ビルの色画像は維持し、遠景外壁・発光・材質データなどを縮小。元PNGとImagegen原画は変更しない。追加の昼夜反射キューブは128px/面。Blender書き出し後に `uv run --with pillow python tool/optimize_stage_textures.py` を実行し、`python3 tool/audit_stage_asset.py` で14MiBの画像上限を検査する。素材の原画・プロンプト・再生成手順は `../04_GAME_ASSETS/3d/stages/akasaka/README.md`。サイズ比較は `qa/texture-resolution.json`。

### 負荷の再現測定

デバッグ拡張 `madogiwa.catchAction` に `action=graphics, json={...}`（5つのbool、`persist=true`は保存する場合だけ）、`action=benchmark, label=..., timeOfDay=day|night` を追加。benchmarkはseed 1・CTOおだてつ・正面・8秒進行時点でシミュレーションを固定し、120フレーム準備後に360フレームのFlutter build/raster時間を取得する。結果は `madogiwa.inspectCatch` の `benchmark` と `STAGE_BENCHMARK` ログに出る。測定中は操作せず、終了後は再起動かstart/resumeで通常プレイへ戻る。

実機／macOSのprofile起動では `--profile --dart-define=STAGE_BENCHMARK=true --dart-define=STAGE_QUALITY=light --dart-define=STAGE_TIME=night` で自動測定できる（標準／昼はそれぞれ `standard` / `day`）。これはCPU側のUI・raster時間で、GPU実行時間・表示FPSではない。今回のiPhoneシミュレーターdebug比較は傾向確認用で、実機性能・旧版との実行速度差は未計測。資産上限と比較結果は `qa/surface-budget.json` / `qa/surface-benchmarks.json` を参照。
